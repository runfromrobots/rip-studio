# Project: RIP Studio

A running portfolio site for "Rip" (Michael Kennedy's studio identity) — primarily a working showcase of AI-built projects (small-business sites, the MK Soap brand, and non-career side projects like Midterm Digest, the Yatesville Creek Paper Boat Race, and Little Big Cat), with "web design agency for small businesses" as a real but secondary offering layered on top, not the site's main identity. This was an explicit repositioning by the site owner ("shift the entire focus... that's what it's become") after the Work section organically grew to be mostly non-client project work — don't revert the homepage copy back to a pure agency sales pitch; the hero, About section, and overall framing should read "here's what gets built here" first and "also available for hire" second. The pricing page, lead-capture form, and Venmo payment flow all stay fully real and functional for when an actual SMB client does come through — the repositioning is about framing/emphasis, not about removing the ability to actually take on paid work. Static site, no build step, no framework — same approach as mikewkennedy.com, deliberately different visual identity.

## Stack

Plain HTML/CSS/JS. No React, no bundler, no dependencies. Fonts via Google Fonts CDN link tags in each HTML file's `<head>`.

## Design system

* **This is a deliberately different visual identity from mikewkennedy.com** — do not reuse its cyan/magenta/near-black hacker theme, its `--cds-` token names, or its VT323/Fraunces/Inter/Plex Mono font stack. Any resemblance between the two sites should be structural (static HTML, token-driven CSS, no build step), never visual.
* **Theme**: inspired by traditional tattoo flash sheets and skate/screen-print art, filtered through a restrained, gallery-style presentation (the "Brian Jones Design" reference point: sparse copy, minimal promotional language, work speaks for itself). Inspiration is drawn from the *genre* (flash-sheet conventions, bold linework, limited fluorescent-accented palettes, screen-print grain), not from any specific living artist's actual artwork or shop branding — do not copy or closely trace tallboy666 / Beer Money Shop's specific illustrations or logo.
* **Colors** (`:root` in styles.css): `--paper` (#EFE6D3, warm cream/bone, like flash-sheet paper) and `--paper-raised` (a shade darker, for card surfaces) as the base; `--ink` (#16130F, warm near-black) for text/linework; `--flash` (#FF2F5E, fluorescent coral-red) as the single primary accent; `--flash-2` (#C6FF3D, acid green) as a secondary accent used sparingly (currently only in the contact section's secondary button); `--stone` (#3B3934, dark warm gray) is the tombstone's solid fill only, not a general-purpose token. Do not introduce additional accent colors.
* **Type**: `--font-tombstone` is now a straight alias of `--font-display` (Anton, bold condensed) — the wordmark and hero tombstone graphic use the exact same face as headings/section titles, not a separate script. History: started as UnifrakturCook (blackletter, read as horror-gothic), then Pacifico (too soft/rounded, read as a coffee-shop logo), then Yellowtail (the closest free approximation of Sailor Jerry-era banner script) — but across those swaps the `--font-tombstone` CSS variable and the Google Fonts `<link>` import drifted out of sync more than once, and by the final Yellowtail pass the variable still said `'UnifrakturCook', serif` while the import only loaded Yellowtail, so the browser silently fell back to generic serif in production (confirmed from a real screenshot — this was never caught because this environment's own test screenshots can't reach Google Fonts at all, so the bug was invisible to every render check made here). The site owner's fix request ("bold consistent font") plus that recurring sync failure are why the separate script was dropped entirely rather than swapped again: one font family for wordmark + tombstone + headings removes the whole class of drift bug and reads as more deliberate. A literal licensed reproduction of Sailor Jerry's own hand-lettering remains available only as a paid font from specialty foundries if the site owner ever wants to revisit a script treatment — don't reintroduce a second display font casually. `--font-body` (Inter) handles all body copy. `--font-mono` (IBM Plex Mono) handles labels, nav links, eyebrows, flash-sheet numbering ("No. 001"), and status tags.
* **When changing a font-family token, grep for every `<link>` tag across every HTML file (not just index.html) and update the CSS variable in the same pass** — this site has no shared header include, so each of the 9+ HTML files carries its own copy of the Google Fonts `<link>`, and the UnifrakturCook/Yellowtail drift happened specifically because a font swap touched the HTML `<link>` hrefs via a sed pass but missed the CSS variable (or vice versa) at least once. Verify both are consistent before considering a font change done.
* **The RIP / tombstone motif is the core brand device**, not just wordplay: traditional tattoo flash sheets already use tombstones as a standard motif (alongside roses, daggers, banners, swallows), so the name and the visual language are meant to reinforce each other. The hero's `.tombstone` element ("RIP — Here lies your old website") is a solid `--stone` fill with no border and white text (`#FFFFFF` for the "RIP" itself, `rgba(255,255,255,0.72)` for the smaller sub-line) — deliberately no stroke/outline and no divider line across it, per the site owner's direction (an earlier `::before` divider line was removed entirely, don't re-add one). Built in pure CSS, no image asset yet; a real illustrated version could replace it later but should keep the same fill-not-stroke, white-on-dark treatment and "epitaph for your old site" framing.
* **Work section uses flash-sheet numbering** (`.flash-number`, "No. 001", "No. 002"...) as the organizing device for the showcase/case-study grid. This is the mechanism for "a collection that updates as we go" — adding a new client project is adding the next numbered card plus its detail page under `/work/`, not a redesign.
* **Any project with a real, deployed URL gets a live iframe preview, not a static screenshot** — regardless of whether its status tag is "Live" or "Demo" — a deliberate choice so the thumbnail updates itself automatically whenever the underlying site changes, no manual re-capture needed. Uses the scaled-iframe technique: the iframe is rendered at a wider virtual viewport (400% of its container for grid thumbnails via `.flash-thumb`, 133.333% for the bigger detail-page preview via `.project-preview`) then shrunk back down with `transform: scale()` (0.25 and 0.75 respectively) so it displays a real desktop layout, not a squished mobile view. Both use `pointer-events: none` on the iframe (it's a preview, not something to interact with — the card/page's own links are what should be clickable) and `sandbox="allow-scripts"` (lets the embedded site's own JS run, e.g. footer-year scripts, without letting it navigate or pop up out of the frame). Confirmed none of `iroquois-lanes.vercel.app`, `orboretum.vercel.app`, `mk-soap.vercel.app`, `runfromrobots.github.io` (Midterm Digest), `ycprb.vercel.app`, or `littlebigcat.vercel.app` send `X-Frame-Options`/CSP `frame-ancestors` headers that would block embedding — if a future project's host does block framing, fall back to `.thumb-placeholder` (dashed border, "Coming Soon"-style text) rather than a broken embed. Projects without a live URL yet use `.thumb-placeholder` on both the grid card and its detail page for visual consistency, not an embed pointed at nothing (no current project is in that state as of this writing — MK Soap, the last one that was, is live now).
* **Buttons**: flat fill only, no outline/ghost style, matching the same convention validated on mikewkennedy.com. `.btn-primary` is `--flash` fill, `.btn-secondary` is `--ink` fill; the dark `.contact` section swaps to `--flash`/`--flash-2` fills since the background is already dark.
* **No dark-mode/light-mode toggle** — this site's whole identity (cream flash-sheet paper background) doesn't have an inverse "dark theme" the way the hacker-themed personal site does. Don't add one without being asked.
* **Flash-sheet paper grain and "stamped" depth are real CSS now, not just concept copy.** For a long stretch the design-system comments described a "flash-sheet paper" and "screen-print grain" concept that was never actually rendered — the site was 100% flat solid color with thin hairline borders, which is why it read as sparse/generic-template despite the font and color system being on-brand. Fixed with two additions, both deliberate, don't strip them back out as "unnecessary":
  - A subtle SVG-noise grain texture on `body::before` (fixed, `pointer-events: none`, `z-index: 999`, 5% opacity, `mix-blend-mode: multiply`) sitting over the whole page. Keep the opacity low (0.04–0.06) — this is paper grain, not visible static; don't crank it up.
  - A "stamped sticker" hard-offset `box-shadow` (solid color, no blur) plus a 2px `--ink` border on every major surface: `.btn` (4px shadow, presses down to 1px on hover/translate), `.tombstone` (static 8px shadow, no hover since it's not interactive), `.flash-card` (2px border + 4px shadow, grows to 7px and lifts slightly on hover), `.price-card` (2px border + 5px static shadow), `.service-card` (2px border + 3px static shadow, lighter touch since Services is the secondary section post-repositioning). Buttons inside the dark `.contact` panel get a `--paper`-colored shadow instead of `--ink` (an ink shadow on an ink background is invisible) — if a new component needs this treatment on a dark surface, use the same override pattern rather than copying the light-surface shadow color.
* The hero includes a three-item checkmark list (`.feature-list.hero-points`, reusing the same checkmark treatment from `pricing.html`'s price cards for visual consistency): "Every project below is live and linked," "Built fast with AI, directed by a person," "Also available to build yours" — rewritten from an earlier, purely-agency version ("Easily make changes any time," "SEO optimized," "Agency-quality design on a SMB budget") as part of the portfolio-first repositioning (see top of file). The old agency-pitch bullets fit a different framing; don't restore them without being asked, and don't casually rewrite the current ones either — they're deliberately ordered portfolio-first, hire-us-second.
* Pricing numbers are deliberately kept off the homepage (services section describes the flat-fee/flat-monthly model in words, not digits) — the sell there is through the work and a direct conversation, not a price table. Real numbers live on the dedicated `pricing.html` page instead. Don't add specific dollar amounts to the homepage without being asked.
* **`pricing.html`** — two flat-fill price cards (`.price-card`): "The Build" ($250 founding-client rate, struck-through $400&ndash;500 list price, one-time) and "The Upkeep" ($29/mo or $290/yr). Below that, an explicit "what's not included" scope note (redesigns/new features/integrations quoted separately, $150&ndash;300) and a "you own it, always" trust strip (domain ownership, no lock-in, 48-hour edit turnaround) — these all come directly from the pricing-model conversation with the site owner and shouldn't be renegotiated without being asked. The `#reserve` section is a lead-capture form, not a payment button by design (see Content status below) — payment happens over Venmo as a separate step after the site owner follows up, not gated behind the form.
* **The `#reserve-form`** on `pricing.html` (business name, contact name, email, phone, need, message) submits via a JS handler in `script.js` that builds a `mailto:` link from the field values and navigates to it — no backend, no third-party form service. This is a deliberate, working no-build-step solution, not a placeholder to be "fixed" — if a real form backend (e.g. Formspree) is wanted later for a proper submissions dashboard, that's an upgrade to raise with the site owner, not something to silently swap in.
* **`ai-approach.html`** — the site's AI stance/values page, added at the site owner's explicit request to mirror mikewkennedy.com's own AI position (human judgment drives every decision; AI, specifically Claude Code, is only ever the execution tool that turns an already-made decision into working code). Structured as a centered `.pricing-hero`-style intro, two `.project-copy` prose sections ("The Stance," "In Practice"), a `.trust-strip` contrasting "What stays human" vs. "What AI builds," and a closing section linking to mikewkennedy.com as further reading. Linked from the footer on every page ("Our Approach to AI," not the main nav — same restrained-nav convention as everything else) and from a line in the homepage's About section. This is a values statement, not a tutorial — don't turn it into a step-by-step "how to use Claude Code" walkthrough like mikewkennedy.com's `how-this-site-was-made.html`; that's a different page with a different job.

## Conventions

* **Title Case for UI Labels**: buttons (`.btn`), eyebrows (`.eyebrow`), form field labels (`.form-field label`), price card labels (`.price-card-label`), status tags (`.status-tag`), and the back-link all use title case ("Start a Project," "Get in Touch," "Business Name"), not sentence case. Minor words (a, the, in, of, to) stay lowercase mid-phrase. This does **not** extend to `<h1>`/`<h2>` headline copy ("Rest assured.", "Design that earns its keep") or body prose/placeholder text, which stay in their existing sentence-case editorial voice — those are deliberately different registers. (One exception exists as of this writing: `pricing.html`'s "Tell Us About Your Business" is used verbatim as both the `#reserve` section's `<h2>` and the message textarea's label, so titling one titled both — pre-existing content repetition, not something to "fix" by de-casing just the heading.)
* **"E-mail," hyphenated**, not "email," everywhere in visible site copy and in the JS-generated inquiry e-mail body (`script.js`) — a deliberate spelling choice by the site owner. This does **not** apply to HTML technical attributes (`type="email"`, `name="email"`, `id="f-email"`) or the `mailto:` scheme itself, which must stay as-is for the form/links to keep working.
* **"RIP," never "R.I.P."** — the brand name and tombstone text write it as a plain three-letter acronym in all caps, no periods, everywhere (wordmark, tombstone graphic, page titles, footer copyright). This was a deliberate site owner correction from an earlier period-separated style; don't reintroduce the periods. This is separate from "Rip" (title case, no periods) used as the person's actual nickname in prose (e.g. the About section's "Who's Rip" eyebrow, "Behind the name is Michael Kennedy") — that's a name, not the acronym, and stays as a normal capitalized word, not all-caps.
